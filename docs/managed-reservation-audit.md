# Opt-in managed reservation audit capture

This source adds local reservation capture to the existing managed Cards service. It is not enabled by default. The legacy constructor/configuration and default V1–V7 migrations remain unchanged. Install the optional V8 contract first, then the derived audit deployment and separate owner coupling with a separately delegated migrator. Installation must run each standalone SQL file as one script; the audit scripts include their own BEGIN/COMMIT. No automatic DDL is supplied.

The derived audit SQL is exactly Jafly134 with only `firefly_audit_writer`/`firefly_audit_reader` replaced by the actual `cards_managed_command`/`cards_managed_reader`. The separate audit guard stays separate. Runtime roles gain no guard membership or private-schema access. Temporary installation CREATE/REFERENCES/USAGE grants are revoked. The separate owner coupling adds no reader grants. The byte-derived generic contract retains its original reader SELECT privileges with no applicable reader RLS policy; an admitted audit export/read adapter remains unavailable.

Construct the audited service overload with the same command factory, client, template, transaction manager, principal port, owner authority, Clock and monotonic supplier as the actual command session. A required `ManagedCardReservationAuditAdmission` must authenticate the current client/staff profile, authorize the resource/action and exact policy revision, and prove its relation to the retained domain actor. Platform tenant is the exact authenticated String; resource tenant is the UUID. The kernel event is a value, not authority. No genuine provider, permissive fallback or automatic audit bean is supplied here.

The actual five-row reservation append/readback, shared Spring Data audit head/event/permanent-outbox append, and owner native pair run inside the original bounded root and physical lease. Event identity and body derive from the retained result, with original native recording time and a domain-separated digest covering every field that determines the five-row graph. The original deadline/time pair can only narrow. Audit failures mark that same invocation rollback-only even when an owner catches the error. Append evidence stays provisional until the owner observes known commit and complete cleanup; a rollback boundary cannot return a successful reservation receipt.

The deferred NOT VALID tenant/event FK is only an existence constraint. Additional deferred owner guards check the original Cards graph/completion and the same xid/backend/session audit graph/completion, exact stream/card/action/process/correlation/causation/time/caller/client/staff/policy/evidence, and new-versus-replay disposition. A private immutable original-nonce pair retains the values admitted in the live Java path. Native guards enforce consistency and finite technical scope; they do not independently authenticate the caller or establish upstream owner permission.

Existing rows remain historical audit **UNVERIFIED**. Installation does not backfill or validate old history. An exact RESERVE replay requires the original full audit event; a legacy reservation without original audit refuses and rolls back any provisional append. RECOVER keeps the existing reader/history scope and does not create or promote mutation audit. Exact replay under a different original audit actor/policy also refuses.

The permanent outbox is export intent, not delivery/ACK state. Delivery leases, independent checkpoints, custody, WORM, retention/holds, global core adoption, upstream account fence/issuer/provider/financial acceptance and DORA acceptance remain separate gates. Source mapping tests do not qualify PostgreSQL schema installation, actual native triggers, original module Maven packaging, or production deployment.
